# 문자 발송 서비스 비교 — 타스온 · 알리고

교육 안내 문자 자동 발송을 붙이기 전에, 지금 쓰는 타스온을 그대로 쓸지 알리고로 옮길지
판단하기 위한 문서다. 공개된 API 규격과 요금표를 직접 확인해 정리했다 (2026-08-18).

## 결론

**알리고로 옮기는 것을 권고한다.** 세 가지가 모두 알리고 쪽이 낫다.

| | 타스온 | 알리고 |
|---|---|---|
| **발송 실패 위험** | 교육 당일 아침 우리 시스템이 살아 있어야 함 | 전날 예약해 두면 끝 |
| **요금 (LMS)** | 50원 (쿠폰 27~45) | **25원** |
| **기능** | 즉시 발송만 | 즉시 발송 + 예약 + 예약 취소 |

**요금은 회차당 1~2만 원 차이로 크지 않다.** 그래서 요금만으로는 옮길 이유가 되지 않지만,
위험이 함께 낮아지므로 어느 쪽으로도 손해가 없다.

**판단의 무게는 발송 실패 위험에 있다.**

## 발송이 안 나가면 어떻게 되는가

타스온 API 에는 예약 발송 기능이 없다. 그래서 교육 당일 아침 07:30 에 **우리 시스템이
직접 문자를 보내야 한다.** 그 시각에 시스템이 멈춰 있으면 그날 교육생 전원이 안내를 받지
못한다. 집중교육이 3일이므로 이 상태를 **3일 연속** 통과해야 한다.

알리고는 전날 통신사에 예약을 등록해 둔다. 등록한 뒤에는 우리 시스템이 꺼져 있어도 문자가
나간다. **위험 구간이 3일에서 예약 등록 순간 하나로 줄어든다.**

이것이 가정이 아닌 이유가 있다. 2026년 8월 7일, 사내 문의 대응 시스템이 멈춰 **6일 동안
아무도 알지 못했다.** 프로그램 오류가 아니라 실행 중이던 창이 닫힌 것이 원인이었다.

그때는 문의 답변이 늦는 정도로 끝났지만, 같은 일이 교육 당일 아침에 일어나면 150명이
접속 정보를 받지 못한다. **되돌릴 방법이 없고 대체할 수단도 없다.**

## 기능 비교

| | 타스온 | 알리고 |
|---|---|---|
| **예약 발송 API** | **없음** | `rdate`(YYYYMMDD) `rtime`(HHMM) |
| **예약 취소 API** | **없음** | 있음 (발송 5분 전까지) |
| 1회 요청 최대 수신자 | 규격에 명시 없음 (콘솔 100건) | **1,000명** |
| MMS 발송 | 지원 | 지원 (이미지 3개까지) |
| MMS 예약 | — | 가능 |
| 발송 결과 조회 | 있음 | 있음 |
| 인증 방식 | `tas_id` + `auth_key` | `key` + `user_id` |

출처: [타스온 API 문서](https://www.tason.com/developer/api) · [알리고 API SPEC](https://smartsms.aligo.in/admin/api/spec.html)

## 요금 비교

교육 안내 문자는 **LMS(장문)** 다. 실제 발송문이 586바이트로, SMS 기준인 90바이트를
크게 넘는다.

| | SMS | **LMS** | MMS |
|---|---|---|---|
| 타스온 | 9.9원 (쿠폰 8~9.5) | **50원** (쿠폰 27~45) | 227원 (쿠폰 65~83) |
| 알리고 | 8.4원 | **25원** | 60원 |

### 한 회차 기준

교육생 137명 + 고정 수신자 16명 = 153명, 집중교육 3일이므로 문자 3회.

```
발송 건수   153명 × 3일 = 459건

타스온 정가   459 × 50원 = 22,950원
타스온 쿠폰가 459 × 27원 = 12,393원
알리고        459 × 25원 = 11,475원
```

**회차당 1~2만 원, 절반 수준이다.** 절대 금액이 작아 이것만으로 옮길 이유는 되지 않지만,
옮기면 함께 줄어드는 항목이다.

MMS 를 보내는 회차에서는 차이가 더 벌어진다 — 153명 1회 기준 타스온 34,731원(쿠폰가
9,945원) 대 알리고 9,180원이다.

## 실제로 달라지는 것 셋

### ① 발송 실패 위험

```
타스온   07:30 에 우리 시스템이 살아 있어야 함 · 3일 연속
알리고   전날 예약 등록 후 끝 · 우리 시스템과 무관
```

타스온으로 가면 시스템이 죽었을 때를 대비한 장치를 따로 만들어야 한다.

- 발송 30분 전 사전 알림 (안 오면 사람이 손쓸 시간 확보)
- 발송 후 결과 알림
- 시스템 밖에서 발송 여부를 확인하는 감시
- 타스온 콘솔 예약 병행 (수작업이 그대로 남는다)

**이 장치들을 다 만들어도 알리고의 기본 동작만 못하다.**

### ② 배치 분할

```
타스온   1회 100건 기준 → 153명이면 2회로 쪼갬 → 일부만 나가는 상태가 생김
알리고   1회 1,000명   → 153명 한 번에 → 부분 실패 자체가 없음
```

부분 실패는 재시도를 까다롭게 만든다. 처음부터 다시 보내면 이미 받은 사람이 두 번 받는다.
그것을 막으려면 발송 이력을 배치 단위로 관리해야 한다 ([docs/04](04-발송이력.md)).

**알리고에서는 이 문제가 발생하지 않는다.**

### ③ 예약 변경·취소

교육 취소, ZOOM 링크 변경, 일정 변경은 실제로 일어난다.

```
타스온   예약을 걸 방법이 API 에 없다
         콘솔로 걸어 뒀다면 사람이 콘솔에 들어가 취소 (발송 5분 전까지)
         시스템은 그 사실을 모름 → 이력과 실제 상태가 어긋남

알리고   예약 취소 API 호출 → 이력도 함께 갱신 → 새 값으로 재등록
         또는 애초에 예약을 안 걸고 발송 직전까지 내용을 고침
```

알리고는 **두 방식 중 상황에 맞는 쪽을 고를 수 있다.** 타스온은 선택지가 없다.

## 타스온에 남는 이점은 하나뿐이다

**이미 쓰고 있다는 것.** 계정·발신번호·요금 체계가 자리 잡혀 있고 콘솔 사용법에 익숙하다.
전환에는 비용과 기간이 든다.

그 밖에 타스온이 더 나은 항목은 찾지 못했다. **알리고는 타스온이 하는 것을 다 하고
예약과 예약 취소를 더 한다.**

```
타스온   즉시 발송 O   예약 X   예약 취소 X
알리고   즉시 발송 O   예약 O   예약 취소 O
```

예약은 **선택**이지 강제가 아니다. 알리고를 쓰면서도 예약을 걸지 않고 07:30 에 직접
보낼 수 있다. 그러면 발송 직전까지 내용을 고칠 수 있어 타스온과 똑같이 동작한다.
필요할 때 예약을 쓰고, 아닐 때 안 쓰면 된다.

## 전환 비용

| 항목 | 소요 |
|---|---|
| 계정 개설 | 즉시 |
| **발신번호 사전등록** | 서류 제출 후 **영업일 3일** |
| └ 통신서비스 이용증명원 발급 | **통신사에서 발급 — 이것이 가장 오래 걸린다** |
| API 키 발급 | 계정 개설 시 |
| 개발 | 발송 코드에서 호출부만 교체 |
| 병행 운영 | 3~4회차 |

필요 서류는 **통신서비스 이용증명원(발급 1개월 이내), 사업자등록증, 담당자 재직증명서**다.

출처: [알리고 발신번호 사전등록 안내](https://smartsms.aligo.in/qna/help_list_detail.html?type=f&seq=79)

## 권고

```
1. 통신서비스 이용증명원을 먼저 발급받는다
   → 어느 쪽으로 가든 필요하고, 가장 오래 걸린다

2. 알리고 계정 개설 · 발신번호 등록

3. 1회차는 그림자 운영
   실제 발송은 기존 방식, 알리고로는 담당자 번호에만 같은 문자 발송
   예약이 07:30 에 정확히 나가는지 · 글자가 깨지지 않는지 · MMS 이미지가 붙는지 확인

4. 1~2회차 병행
   알리고로 실제 발송하되 기존 예약도 걸어두고, 나간 것을 확인하면 기존 예약 취소

5. 알리고 단독
```

**전환 여부와 무관하게 1번은 지금 시작할 수 있다.**

## 판단이 필요한 것

기술 검토로는 답할 수 없는 항목이다.

- 타스온 사용이 **계약이나 기관 지정**에 묶여 있는가
- 타스온 쿠폰가가 실제로 얼마인가 (충전 금액에 따라 달라진다)
- 발신번호 재등록 절차를 진행할 수 있는가

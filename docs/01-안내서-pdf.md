# 안내서 PDF 생성

`src/edu_notify/pdf.py` 를 고치기 전에 읽는다.

## 왜 PPT 를 거치지 않나

PPT → PDF 변환에는 PowerPoint 가 필요하다. EMS 는 Vercel(리눅스)에서 돌아가므로
PowerPoint 도 LibreOffice 도 쓸 수 없다. 대체 도구로 변환하면 글꼴이 없어 줄이 밀리고
표가 깨진다. 교육생에게 나가는 문서라 모양이 흐트러지면 안 된다.

그래서 **기존 안내서 PDF 자체를 틀로 쓴다.** 바뀌는 세 줄만 지우고 다시 찍고, 체크리스트
링크 주소를 갈아끼운다. 나머지는 손대지 않으므로 레이아웃이 틀어질 여지가 없다.

검토했다가 접은 것들:

| 방법 | 왜 안 썼나 |
|---|---|
| PPTX 템플릿을 치환 후 PDF 변환 | 결국 PowerPoint 가 필요해 원점 |
| 안내서를 HTML 로 다시 만들어 PDF 생성 | 디자인을 픽셀 단위로 재현해야 하고 계속 검증해야 함 |
| 담당자 PC 의 PowerPoint 로 변환 | 그 PC 가 켜져 있어야 하고 클라우드 ↔ 사무실 통신이 필요 |

## 값을 어떻게 찾나

좌표를 박아 두지 않는다. 표의 가로선으로 칸을 나눈 뒤, 각 칸에서 라벨(`교육명`·`일시`·
`장소`)을 찾고 그 칸의 맨 윗 값 줄을 바꿀 대상으로 잡는다. 그래서 과정명 형태가 다르거나
(`①`·`②`·`⑤`·`⑦` 이 붙은 것) 일정이 하루짜리든 사흘짜리든 같은 코드로 처리된다.

라벨을 기준선으로 삼지 않는 이유가 있다 — `일시` 칸만 두 줄(일정 + `* 환경 점검`)이라
라벨이 세로 가운데로 정렬되어 어느 값 줄과도 기준선이 맞지 않는다. 라벨 기준으로 찾으면
템플릿 10종 전부에서 `일시` 를 놓친다.

## 옛 글자는 가리지 않고 지운다

흰 사각형으로 덮는 것으로는 부족하다. 눈에는 안 보여도 글자는 PDF 안에 그대로 남아서,
**복사하거나 검색하면 지난 회차 Zoom 비밀번호가 나온다.**

```
화면    Zoom 회의 ID : 123 4567 8901 / PW : green5
복사    Zoom 회의 ID : 832 5527 6350 / PW : green    ← 지난 회차 비밀번호
```

그래서 내용 스트림에서 해당 글자를 그리는 명령 자체를 뺀다. 단, 라벨이 값과 같은 줄에
있으므로 가로 위치가 `X_MIN`(114pt) 이상인 것만 지운다. 이 조건을 빼면 `교육명`·`일시`
라벨까지 사라진다.

`scripts/verify.py` 가 매번 이걸 검사한다. 눈으로는 확인되지 않는 종류의 문제다.

## 글꼴

에스코어 드림을 쓴다. PPT 에 지정된 글꼴인데, 과거 안내서들은 PDF 로 저장하는 시점에
그 PC 에 글꼴이 없어 다른 글꼴로 대체되어 나갔다. 즉 담당자가 PPT 화면에서 보던 글꼴과
교육생이 받은 PDF 의 글꼴이 원래부터 달랐다.

줄마다 굵기가 다르다. 원본 안내서와 잉크량(글자가 차지하는 어두운 픽셀 비율)을 맞춰
후보를 하나씩 재서 정했다.

| 줄 | 글꼴 | 원본과 차이 |
|---|---|---|
| 교육명 · 일시 | 드림 5 Medium + 테두리 0.2 | 0.0087 (후보 7종 중 최소) |
| 장소 | 드림 4 Regular, 테두리 없음 | 0.0008 (사실상 일치) |

`장소` 가 굵지 않은 것은 PPT 원본을 따른 것이다.

원본은 굵기를 **테두리 덧그리기**로 표현한다(에스코어 드림에 굵은 짝이 따로 없어서).
그 두께를 원본 값(`0.31543`) 그대로 쓰면 과해진다 — 원본은 대체된 글꼴(Regular) 기준이고
드림 5 는 이미 Medium 이라 한 단계 굵기 때문이다. 잉크량으로 재면 `0.31543` 은 차이
0.0508, `0.2` 는 0.0059 다.

에스코어 드림은 `.otf` 로 배포되는데 안쪽 곡선이 3차 베지어라 reportlab 이 못 읽는다.
`src/edu_notify/fonts.py` 가 2차로 근사해 TTF 로 바꾼다. 변환 결과는 `.fontcache/` 에
남겨 두고 재사용한다.

> **배포 조건 확인 필요.** 무료 사용·재배포는 허용되지만 (1) 이 코드가 OTF 를 TTF 로
> 변환해 쓰고 (2) 만들어진 PDF 에 글꼴이 부분 임베드된다. 실제 운영 배포 전에 배포처에
> 확인한다.

## 확인된 범위

안내서 템플릿 10종 × (평범한 값 / 가장 긴 값) = **20건 통과**.
`Zoom` 과 `ZOOM` 표기가 섞인 파일, 과정명에 원문자가 붙은 파일에서도 동작한다.

가장 긴 값으로도 칸을 넘치지 않는다 — 최대 340pt, 칸 폭 383pt.

```powershell
uv run python scripts/verify.py
```

## 고치기 전에 읽을 것

만들면서 실제로 걸렸던 것들이다. 그린 파일 하나로만 확인했을 때는 1·2 번만 보였고,
템플릿 10종을 전부 돌려 보고서야 3·4·5 번이 드러났다.

1. **옛 글자를 가리기만 하면 PDF 안에 남는다.** 위 [옛 글자는 가리지 않고 지운다](#옛-글자는-가리지-않고-지운다).
2. **값만 지워야 한다.** 라벨이 값과 같은 줄이라 줄 단위로 지우면 라벨까지 사라진다.
3. **라벨 기준으로 값을 찾으면 안 된다.** `일시` 칸만 두 줄이라 라벨이 가운데 정렬되어
   어느 값 줄과도 기준선이 맞지 않는다. 표 가로선으로 칸을 잡는다.
4. **기준선이 1.6pt 어긋난다.** `pdfplumber` 가 보고하는 y 와 내용 스트림의 y 가 다르다.
   지우고 찍을 때는 스트림에서 직접 찾은 값을 쓴다.
5. **`장소` 줄은 기준선이 갈려 있다.** Zoom ID 숫자가 2.85pt 아래에 찍혀 있어 다른 줄로
   분류된다. 맨 윗 기준선에서 5pt 안쪽은 같은 줄로 합친다.
6. **굵게를 줄마다 명시적으로 켜고 꺼야 한다.** 끄는 쪽을 생략하면 앞 줄 설정이 남아,
   굵게가 아닌 `장소` 줄이 앞 줄 테두리색(빨강)으로 물든다.

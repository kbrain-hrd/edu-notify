# 발송 계획

안내서 PDF 생성 다음에 붙일 것. 아직 구현하지 않았다.

## 무엇을 자동화하는가

지금은 회차마다 이렇게 한다.

```
EMS 에서 교육생 명단을 구글시트로 내려받는다
      ↓
번호를 100개씩 끊어 타스온에 붙여넣는다
      ↓
교육 전주에 안내 메일을 보낸다
      ↓
교육 당일 아침에 문자를 예약한다
```

명단이 EMS 에 이미 있으므로 내려받을 이유가 없다. EMS 안에서 회차를 고르고 값 네 개를
넣으면 메일과 문자가 나가게 한다.

## 이메일과 문자는 성격이 다르다

| | 이메일 | 문자 |
|---|---|---|
| 언제 나가나 | 교육 전주 | 교육 당일 07:30 |
| 실제로 보내는 주체 | 우리(EMS)가 즉시 발송 | **타스온**이 예약 시각에 발송 |
| 경로 | 기관 자체 메일서버 SMTP | 타스온 API |
| 1회 건수 제한 | 없음 (시간당 제한은 확인 필요) | **100건** |
| 버튼을 누르면 | 바로 나간다 | 예약만 걸린다 |
| 잘못 눌렀을 때 | 되돌릴 수 없다 | 발송 5분 전까지 취소 가능 |

**문자를 우리 쪽 스케줄러로 07:30 에 쏘지 않는다.** 그러려면 담당자 PC 가 그 시각에 켜져
있어야 하는데 보장할 수 없다. 타스온 예약에 미리 등록해 두면 PC 가 꺼져 있어도 나간다.

타스온이 며칠 전 예약까지 허용한다면 **전주에 한 번만** 화면을 열어 메일 발송과 문자 예약을
같이 끝낼 수 있다. 그러면 당일 아침에 담당자가 할 일이 없다.

## 100건 제한이 구조를 바꾼다

137명이면 100 + 37 로 쪼개야 한다. 쪼개는 순간 지금까지 없던 상태가 생긴다 —
**일부만 나가고 일부는 실패한 상태**다.

여기서 함정은 재시도다. 배치 2 만 실패했는데 처음부터 다시 돌리면 배치 1 의 100명이
같은 문자를 두 번 받는다.

그래서 이 기능의 절반은 발송이 아니라 **어디까지 보냈는지 기록하는 일**이다. 배치 단위로
남기고 재시도는 남은 것만 집는다. 버튼이 두 번 눌리거나 서비스가 재시작돼도 같은 장치가 막는다.

> 수작업으로도 이미 겪는 문제다. 100개씩 끊어 붙여넣다 두 번째 묶음에서 헷갈리면 똑같이
> 벌어진다. 다른 점은 사람은 대개 이상함을 눈치채고 기계는 눈치채지 못한다는 것이다.

## 승인은 없애지 않는다

줌 링크 하나 틀리면 교육생 전원이 못 들어온다. 발송 화면에서 미리보기를 확인하고
버튼을 누르는 것이 승인이다. 화면에는 발송문 전문과 함께 **기계가 미심쩍게 본 것**을
같이 싣는다 — "줌 링크가 지난 회차와 동일합니다" 같은 것.

## 아직 정하지 않은 것

여기 있는 항목은 임의로 결정하지 않는다.

- **타스온 예약 API 지원 여부** — 안 되면 07:30 에 우리가 직접 쏘는 구조가 되고,
  그 시각 PC 가 켜져 있어야 한다. 구조가 눈에 띄게 약해진다
- **며칠 전까지 예약을 걸 수 있는가** — 일주일 전이 되면 전주에 한 번으로 끝난다
- **기관 메일서버 SMTP 허용 여부와 시간당·첨부 용량 제한** — 제한이 빡빡하면 나눠 보내며
  간격을 둬야 한다
- **발신번호 사전등록** — 문자는 법적으로 필수다. 타스온 계정에 등록돼 있는지 확인
- **개인정보 취급** — 명단은 git 제외, 로그에는 번호를 마스킹, 회차 종료 후 보관 기간
- **실패 건을 누가 보는가** — 반송된 메일과 결번 문자
